# Lightsail deployment: wapp.neorizsolutions.com

Frontend, API, PostgreSQL and the delivery retry worker run together on one Lightsail instance. Caddy supplies HTTPS and renewal. Only ports 80 and 443 are published; PostgreSQL and Django are private to the Docker network. This preserves the existing Django login, staff, booking and WhatsApp workflows. Vercel is not required for this deployment.

## Server and DNS

Use a Linux Ubuntu instance in Mumbai (ap-south-1) with public IPv4. The 4 GB RAM / 2 vCPU bundle medium_3_1 is listed by AWS at USD 24/month as of 16 November 2026; taxes, snapshots and usage outside bundle allowances are additional. This is a starting capacity, not a load guarantee.

Actual deployment on 16 November 2026: the new account rejected the 4 GB plan. The backend uses small_3_1 (2 GB RAM, USD 12/month) with 2 GB swap. Monitor memory and upgrade after AWS lifts the restriction if load requires it. See [deployed server details](DEPLOYED.md).

Attach a static IPv4 address. In the Lightsail firewall, allow TCP 80 and 443 publicly and restrict TCP 22 to your administrator IP. Do not open 5432 or 8000. Point the A record for wapp.neorizsolutions.com to the static address. Remove any conflicting AAAA record unless IPv6 has been configured and tested. Follow [AWS static IP instructions](https://docs.aws.amazon.com/lightsail/latest/userguide/lightsail-create-static-ip.html) and [firewall documentation](https://docs.aws.amazon.com/lightsail/latest/userguide/understanding-firewall-and-port-mappings-in-amazon-lightsail.html).

Install Docker Engine with its Compose plugin using the [official Ubuntu installation instructions](https://docs.docker.com/engine/install/ubuntu/). Copy the application into /opt/wapp with ownership granted to your deployment user. Exclude .git, .venv, development databases, .env files, artifacts and backups. Do not copy development accounts into production.

On a fresh Ubuntu instance, deploy/bootstrap.sh automates that installation using Docker's official apt repository. Run it as root or provide it as Lightsail launch user data, then reconnect as ubuntu so the Docker group membership applies. It has not been run against AWS until provisioning is approved.

## Configure and release

On the instance, in the project directory:

```sh
python3 deploy/lightsail.py init --domain wapp.neorizsolutions.com
chmod 600 .env.lightsail
```

The init command generates independent Django and PostgreSQL secrets and refuses to overwrite an existing configuration. Add your Gemini and Meta credentials directly to .env.lightsail. Leave WHATSAPP_ENABLED=False until webhook credentials and staging checks pass. Database passwords generated by init are URL-safe; if replacing one, use hexadecimal characters and update the database role password as well. Editing an environment file alone does not change an initialized PostgreSQL password.

```sh
python3 deploy/lightsail.py deploy
python3 deploy/lightsail.py admin
python3 deploy/lightsail.py status
```

To defer DNS and the public HTTPS proxy, use `python3 deploy/lightsail.py deploy --backend-only`. Django binds to the server's loopback port 8000, so the API can be checked over SSH without exposing the application server or database publicly. For example, on the instance use `curl -H 'Host: wapp.neorizsolutions.com' -H 'X-Forwarded-Proto: https' http://127.0.0.1:8000/health/`. Public domain access remains unavailable until DNS and the proxy are enabled.

Deployment builds the app, starts PostgreSQL, makes a database backup, checks Django settings, stops application traffic for a maintenance window, applies migrations, and starts the healthy web container, retry worker and HTTPS proxy. If migrations fail, traffic remains stopped so staff can inspect the error. Do not restart an older app against an incompatible schema. This deployment is a single instance and does not provide high availability.

Caddy obtains certificates after DNS resolves to the instance and ports 80/443 are reachable. Its persistent certificates volume allows renewals without losing certificate state. [Caddy's proxy documentation](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) describes the forwarded headers used by Django here.

Check https://wapp.neorizsolutions.com/health/, login, static styles, customer access, staff permissions, a booking and human handover. Set the Meta webhook to https://wapp.neorizsolutions.com/api/whatsapp/webhook/ and verify a signed message, duplicate delivery and reply using a test number before enabling live traffic. The retry worker runs the existing retry_whatsapp command once a minute; UNKNOWN/BLOCKED deliveries continue to require staff review.

## Backups and monitoring

```sh
python3 deploy/lightsail.py backup
docker compose --env-file .env.lightsail -f docker-compose.lightsail.yml logs --tail 100 web retry proxy
```

Schedule `python3 /opt/wapp/deploy/lightsail.py backup` daily using the deployment user's cron. Each successful backup is a custom-format PostgreSQL dump with its archive index checked; this check is not a restoration test. Copy backups to encrypted off-instance storage, set retention, and test restoring into a separate database before launch. Backups on the same Lightsail disk do not protect against instance loss. Preserve .env.lightsail securely and snapshot the knowledge and certificates volumes. Never run `docker compose down -v` on production.

Monitor the public HTTPS health endpoint, disk space, RAM and delivery errors. Logs are rotated to three 10 MB files per service. Configure alerts and confirm the off-instance backup schedule before using the service for real customers. The [general production guide](PRODUCTION.md) covers HSTS options and release rollback constraints.
